# Инструкция по сборке и запуску Schedule в Docker

**Docker-образ:** `ghcr.io/h0llar/schedule:latest`  
**Реестр:** GitHub Container Registry (GHCR)  
**Порт приложения:** `5000`  
**Командная оболочка:** Windows PowerShell

---

## 1. Требования
***Это нужно для сборки, инструкция для запуска ниже***

Перед началом необходимо установить:

- Docker Desktop для Windows.
- Windows 10 или Windows 11.
- Исходный код проекта Schedule (для самостоятельной сборки).

Docker Desktop должен быть запущен.

## 2. Структура проекта

Перед сборкой убедитесь, что в корневой папке проекта находятся необходимые файлы:

```text
Schedule/
│
├── Dockerfile
├── .dockerignore
├── requirements.txt
├── app.py
├── models.py
├── forms.py
├── routes.py
├── main.py
│
├── instance/
├── static/
└── templates/
```

В Dockerfile присутствовуют команды запуска:

```dockerfile
CMD ["python", "app.py"]
```

И команды для копирования файлов проекта в образ:

```dockerfile
COPY . .
```

## 3. Сборка Docker-образа

Откройте PowerShell и перейдите в корневую папку проекта:

```powershell
cd "ПУТЬ_К_ПАПКЕ_ПРОЕКТА"
```

Например:

```powershell
cd "C:\Users\User\Desktop\Schedule\ScheduleConstructor v2.1.7.106\Schedule"
```

Выполните сборку:

```powershell
docker build --no-cache -t ghcr.io/h0llar/schedule:latest .
```

Параметры команды:

- `docker build` — сборка Docker-образа.
- `--no-cache` — сборка без использования кэшированных слоёв.
- `-t` — присвоение имени и тега образу.
- `.` — использование текущей папки как контекста сборки.

После завершения сборки проверьте наличие образа:

```powershell
docker images
```

## 4. Проверка команды запуска приложения

Убедитесь, что Docker-образ содержит команду запуска Python-приложения:

```powershell
docker image inspect ghcr.io/h0llar/schedule:latest --format 'Entrypoint={{json .Config.Entrypoint}} Cmd={{json .Config.Cmd}}'
```

Ожидаемый результат:

```text
Entrypoint=null Cmd=["python","app.py"]
```


## 5. Скачивание образа на другом компьютере

На компьютере, где необходимо запустить Schedule, установите и запустите Docker Desktop.

Затем скачайте образ через Windows Powershell:

```powershell
docker pull ghcr.io/h0llar/schedule:latest
```


## 6. Запуск контейнера через командную строку

Для запуска приложения выполните:

```powershell
docker run -d --name schedule -p 127.0.0.1:5000:5000 --restart unless-stopped ghcr.io/h0llar/schedule:latest
```

Описание параметров:

| Параметр | Назначение |
|---|---|
| `-d` | Запуск контейнера в фоновом режиме |
| `--name schedule` | Имя контейнера |
| `-p 127.0.0.1:5000:5000` | Проброс порта 5000 на локальный компьютер |
| `--restart unless-stopped` | Автоматический перезапуск контейнера после перезагрузки Docker, если контейнер не был остановлен вручную |
| `ghcr.io/h0llar/schedule:latest` | Имя запускаемого Docker-образа |

После запуска приложение будет доступно в браузере:

```text
http://localhost:5000
```

Привязка к `127.0.0.1` разрешает доступ через localhost на этом компьютере. Для доступа с других устройств локальной сети потребуется отдельно настроить сетевой доступ.

## 7. Примеры команд управления контейнером

**Проверка запущенных контейнеров:**

```powershell
docker ps
```

**Просмотр всех контейнеров, включая остановленные:**

```powershell
docker ps -a
```

**Просмотр логов приложения:**

```powershell
docker logs schedule
```

**Просмотр логов в режиме реального времени:**

```powershell
docker logs -f schedule
```

Для выхода из просмотра логов нажмите `Ctrl + C`. Это не останавливает контейнер, запущенный в фоновом режиме.

**Остановка приложения:**

```powershell
docker stop schedule
```

**Повторный запуск остановленного контейнера:**

```powershell
docker start schedule
```

**Перезапуск контейнера:**

```powershell
docker restart schedule
```

**Удаление контейнера:**

```powershell
docker rm -f schedule
```

Внимание: удаление контейнера не удаляет сам Docker-образ.

## 8. Обновление приложения

Когда выходит новая версия Schedule, необходимо:

**Шаг 1.** Перейти в папку с обновлённым исходным кодом.

**Шаг 2.** Собрать новый образ:

```powershell
docker build --no-cache -t ghcr.io/h0llar/schedule:latest .
```

**Шаг 3.** Загрузить его в GitHub:

```powershell
docker push ghcr.io/h0llar/schedule:latest
```

**Шаг 4.** На компьютере, где работает приложение, скачать новую версию:

```powershell
docker pull ghcr.io/h0llar/schedule:latest
```

**Шаг 5.** Удалить старый контейнер:

```powershell
docker rm -f schedule
```

**Шаг 6.** Создать контейнер заново:

```powershell
docker run -d --name schedule -p 127.0.0.1:5000:5000 --restart unless-stopped ghcr.io/h0llar/schedule:latest
```

## 9. Проверка работоспособности

После запуска выполните:

```powershell
docker ps
```

Убедитесь, что контейнер `schedule` имеет статус `Up`.

Затем откройте браузер:

```text
http://localhost:5000
```

Если приложение не открывается, проверьте логи:

```powershell
docker logs schedule
```
